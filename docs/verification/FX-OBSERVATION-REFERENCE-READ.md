# Bounded saved FX observation reference read

`GET /api/v1/fx-snapshots/{snapshot_id}/observation-references` adds one source read while preserving the six aggregate operations and existing run body. It supplies actual persisted observation identities; it does not register sources, fetch providers, infer a quote or calculate a conversion.

The query requires an account, distinct base/quote pair and exact source cutoff. Optional `effective_at_lte` defaults to the cutoff and cannot follow it. The aggregate picker sends the exact earlier instant of its saved account valuation and selection cutoff. The source header must have been effective and first known by the cutoff; row effective dates are independently bounded by `effective_at_lte`.

The request returns at most25 whole rows in descending `(effective_at,id)` order. The read fetches at most26 rate rows, including one continuation witness, through `ix_fx_observation_reference_page(owner_id,snapshot_id,base,quote,effective_at,id)`. Its equality prefix, upper time bound and tuple continuation match the backward B-tree scan. There is no count, offset, full-ID preload, collection membership allocation, Python filtering or automatic page walk. Two differently dated observations cannot collapse into a guessed identity. Empty authorized pages are explicit.

Authorization is metadata first: current analytics/portfolio token scopes plus current active principal, durable grants and active owned account/connection; then original/current source license STORE/DISPLAY, configured provider, actual original/current acquisition STORE/DISPLAY, effective source retention and permanent source marker absence. The existing canonical acquisition predicate validates original publication/attempt/request/grant/scope provenance, not a fabricated local entitlement. The same checks run at the final clock fence before returning a page, including empty and subsequently conditional304 responses. Current scope rows are share-locked in the existing sources owner transaction. No financial rate column is selected before this authority succeeds.

A request executes two principal metadata queries (exactly two accepted grant rows each), two single-snapshot source metadata queries and one rate query. Each source query calls the existing acquisition predicate twice; its internal work consists of fixed original identity lookups and indexed latest-current authority lookups, not a fanout inventory. These metadata costs are additional to the26 financial-row cap. Source queries include original/current acquisition grant IDs/digests/expiry in the cursor fingerprint. Cursors bind owner/actor/current principal grants/account/snapshot digest/source authority/pair/cutoff/effective bound/page limit; no server cursor metadata is written.

Migration0030 owns the additive index and its downgrade. The ORM declaration is delivered with this read. No additional migration number or published migration changes are introduced.

Regression sources cover real normal FX ingestion over40 dates and two pairs; exact amounts and actual row UUIDs;25+15 pages across service restart; one-microsecond valuation bound; independent known-at rejection; cursor account/pair/cutoff/effective/limit substitution; foreign ownership and durable grant revocation before rates; final token-clock expiry after a rate query; actual acquired FX publication with independent current STORE/DISPLAY denials; and permanent retention markers after grants are restored. API/client/contract sources cover authentication before malformed input, strict bounds, exact timestamp forwarding, closed responses, denied conditional replay and the intentional source operation count16.

These regression sources were authored externally. No imports, generator runs, migrations, builds, lint, type checks, tests or browser gates were executed by their author; root owns integration and validation.
